Restore the Tecplore Website

Last updated: 6 November 2026. Keep this file up to date when anything below changes.

This guide is for anyone looking after tecplore.com when the usual maintainer isn't available. You need access to GitHub and Hostinger, and to Cloudflare for domain problems. No coding is needed if you follow the steps in order.

Three rules that prevent most damage

1. Take a backup before you change anything (Part 2).

2. Never empty or delete the main-website folder. It holds files that are not in GitHub.

3. Leave .htaccess untouched.

Part 1: Find out what is wrong

Don't rebuild yet. A rebuild only fixes missing or broken website files.

What you seeLikely causeWhat to do

Part 2: Take a backup

  1. Log in to Hostinger and open File Manager.
  2. Go to public_html, then right-click main-website and choose Compress, as a zip.
  3. Download that zip to your computer, then delete it from the server.
  4. Also check Backups in Hostinger. If a recent backup of the files and database exists, restoring it may be the fastest fix of all.

Part 3: Build the website from GitHub

One-time setup

  1. Install Node.js, the LTS version. The site was last built with version 24.
  2. Install Git.

Get the code

  1. Open a terminal in a folder of your choice and run: 
    git clone https://github.com/Tecplore-innovations/Tecplore_website.git
cd Tecplore_website
git checkout main

    Change main to the correct branch if the note above says so.

  2. Install what the project needs: 
    npm ci
  3. In the project folder, create a file named .env.local containing these two lines. Without them, Teacher Resources will be empty. They aren't secret, but the file is not kept in GitHub. 
    NEXT_PUBLIC_API_BASE_URL=https://tecplore.com/main-website/api
NEXT_PUBLIC_ASSET_BASE_URL=https://tecplore.com

Build

If you run npm run dev, stop it first with Ctrl+C. Building beside it breaks it.

  1. Run: 
    npm run build

    It should end by listing the pages, and a folder named out appears. Warnings about <img> are normal.

  2. If it fails with Failed to fetch Source Sans 3 from Google Fonts, this is a network problem, not a code problem. Force IPv4 and build again. In PowerShell: 
    $env:NODE_OPTIONS = "--dns-result-order=ipv4first --no-network-family-autoselection"
npm run build
$env:NODE_OPTIONS = ""

Zip it

  1. Open the out folder.
  2. Select everything inside it and zip those files. Don't zip the out folder itself, or the files will land one level too deep. index.html must be at the top level of the zip.
  3. New version of the site only: check that highlights are off for the live site. In src/lib/confirm.ts, SHOW_CONFIRM_HIGHLIGHTS must be false. If it isn't, change it and build again. If that file doesn't exist, skip this step.

Part 4: Upload to Hostinger

  1. In File Manager, open public_html/main-website.
  2. Upload your zip into this folder.
  3. Extract it here, and choose to overwrite existing files.
  4. Delete the zip from the server. Anyone could otherwise download it.
  5. Do not delete anything else. The zip contains no .htaccess, so yours stays as it is.

Check it

  1. Open tecplore.com in a private window, which avoids old saved copies.
  2. Open a few pages directly, for example /about-us and /faq, and refresh them.
  3. Check that Teacher Resources shows its list.
  4. Send one test message from the Contact page and confirm it reaches the Google Sheet.
  5. If pages still look old, purge the cache in Cloudflare: Caching, then Purge Everything.

Part 5: If the whole folder was lost

First try Backups in Hostinger, as it restores everything in one go. If there is no backup:

  1. Recreate public_html/main-website and follow Parts 3 and 4.
  2. Recreate .htaccess from Part 7.
  3. Teacher Resources API: upload server-api/get_resources.php from the project to main-website/api/. Edit that server copy and fill in the database name, user and password. Find these under Databases in Hostinger, and reset the password there if nobody has it. Never put the real values in GitHub.
  4. Database: if it was lost too, restore it from Hostinger's database backups.
  5. Photos and station details from /site-admin: these can't be rebuilt from GitHub. Restore them from a backup, or add them again.
  6. New access key: see below.

Create a new key for /site-admin

The key is not in GitHub. If it's lost, make a new one. This only applies once the new version of the site is live. Run this in the project folder:

node -e "const c=require('crypto'),f=require('fs');const k=c.randomBytes(24).toString('base64url');f.mkdirSync('site-admin-setup',{recursive:true});f.writeFileSync('site-admin-setup/ACCESS-KEY-keep-private.txt',k+'\n');f.writeFileSync('site-admin-setup/admin-key.php','<?php\nreturn [\'key_sha256\' => \''+c.createHash('sha256').update(k).digest('hex')+'\'];\n')"
  1. Upload site-admin-setup/admin-key.php to main-website/site-api/, replacing any old one.
  2. Keep ACCESS-KEY-keep-private.txt somewhere safe. Never upload it. That one line is the password for /site-admin.

Part 6: SSL error 525

  1. In Hostinger, open SSL and check the domain shows Active. Install it if it doesn't.
  2. If it gets stuck on Installing, go to Cloudflare, DNS, and set that record to DNS only (grey cloud).
  3. Wait for Active in Hostinger, then set the record back to Proxied (orange cloud).

Do not switch Cloudflare's SSL mode to Flexible. It weakens security for the whole site.

Part 7: Copy of .htaccess

Only use this if the file is missing. It goes in public_html/main-website, named exactly .htaccess. Turn on Show hidden files in File Manager to see it.

If the file on the server is ever changed, update this copy too.

# Define media types
AddType image/avif .avif
AddType image/webp .webp
AddType application/pdf .pdf

# Remove the restrictive header first
Header always unset X-Frame-Options

# Allow the site to frame itself
Header set X-Frame-Options "SAMEORIGIN"
# Alternative for modern browsers
Header set Content-Security-Policy "frame-ancestors 'self' https://tecplore.com https://www.tecplore.com"

# Main website rules
RewriteEngine On

# Serve static files directly by extension, with no rewriting
RewriteRule \.(pdf|avif|webp|jpg|jpeg|png|gif|ico|css|js|woff2|mp4|webm|txt)$ - [L]

# Serve clean URLs for static .html pages
RewriteCond %{REQUEST_FILENAME}.html -f
RewriteRule ^(.+?)/?$ $1.html [L]

# Redirect folders to their index.html
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteCond %{REQUEST_FILENAME}/index.html -f
RewriteRule ^(.*)$ $1/index.html [L]

# Fallback for client-side routes
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.html [QSA,L]

# Error handling
ErrorDocument 404 /404.html

# Cache static assets
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/avif "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType application/pdf "access plus 1 month"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType text/javascript "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType application/x-javascript "access plus 1 month"
  ExpiresByType font/woff2 "access plus 1 year"
</IfModule>

Keep these safe

  • Logins for GitHub, Hostinger and Cloudflare, stored with more than one trusted person.
  • The /site-admin access key.
  • A regular download of main-website and the database.
